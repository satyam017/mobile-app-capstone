# Mobile App User Stories

Nine user stories for the Mindful meditation capstone application.

## 1. Login

### User Story
As a registered user, I want to log in using my email and password so that I can securely access my account.

### Acceptance Criteria
- User can enter email and password.
- User can submit the login form.
- Invalid credentials display an error message.
- Successful login takes the user to the home screen.

---

## 2. Signup

### User Story
As a new user, I want to create an account so that I can use the application.

### Acceptance Criteria
- User can enter username, email, and password.
- User can submit the registration form.
- Invalid or missing information displays an error message.
- Successful registration takes the user to the login screen.

---

## 3. Homepage

### User Story
As a user, I want to view my homepage so that I can see a personalized welcome message and available meditation sessions.

### Acceptance Criteria
- Welcome message with the logged-in username is displayed.
- Popular and daily meditations are displayed.
- App logo/brand appears in the header.
- User can navigate to other sections of the application.

---

## 4. Detail Screen

### User Story
As a user, I want to view the details of a meditation so that I can understand the practice and its instructions.

### Acceptance Criteria
- Meditation title is displayed.
- Meditation description is displayed.
- Meditation instructions are displayed.
- User can return to the previous screen.

---

## 5. Settings Menu

### User Story
As a user, I want to access a settings menu so that I can navigate to account and application options.

### Acceptance Criteria
- Settings menu can be opened from navigation.
- User can access settings, favorites, reminders, and related items.
- User can log out from the menu.
- User can return to the home screen.

---

## 6. Settings Screen

### User Story
As a user, I want to change application settings so that I can personalize my experience.

### Acceptance Criteria
- User can change preferences such as dark mode, sound, and notifications.
- User can save settings.
- Saved settings are retained when the application is reopened.
- User can update profile or password where available.

---

## 7. Persistent Data

### User Story
As a user, I want my application data to be stored persistently so that my information remains available after closing and reopening the application.

### Acceptance Criteria
- Application data can be saved to local storage.
- Saved data can be retrieved.
- Data remains available after restarting the application.
- User can update or remove saved data where applicable.

---

## 8. External API

### User Story
As a user, I want the application to retrieve information from an external API so that I can view up-to-date content.

### Acceptance Criteria
- Application can request data from an external API.
- Retrieved information is displayed to the user.
- Loading status is displayed while data is being retrieved.
- An appropriate error message is displayed if the API request fails.

---

## 9. Notifications

### User Story
As a user, I want to manage notifications and reminders so that I can control when I receive alerts.

### Acceptance Criteria
- User can enable notifications.
- User can disable notifications.
- User can create and manage reminders.
- User can trigger a test notification alert.
- Notification preferences are saved.
